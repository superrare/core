# Route cart payments through validated intermediate custody

The cart accepts platform-signed, order-wide Universal Router command plans and forwards them as opaque programs, including the signed `routerValue`. A dedicated `CartRoutePolicy` performs only shallow default-deny checks for the permitted command families: Permit2 transfer-from, sweep, wrap/unwrap, V2/V3 swaps, and V4 swap. Universal Router remains responsible for decoding command inputs and validating paths, recipients, payer flags, V4 actions, slippage, refunds, and exact-input/output semantics. Swap outputs return to Cart for aggregate balance-delta validation before payout. Both unused input and output above signed line obligations are favorable execution variance belonging to the configured protocol recipient under the signed fixed quote.

The policy rejects command flags, unsupported command families, empty programs, input-count mismatches, and oversized programs. It does not inspect opaque route contents. Cart snapshots ETH, WETH, the payment token, and every non-native settlement currency named by the order; it pools ETH/WETH only for incremental solvency, then delivers each representation exactly and captures positive supported-currency deltas as protocol spread. It rejects nonzero pre-existing payment-token approvals, restores all tracked Cart balances to their baselines, and clears the temporary payment-token approvals. Universal Router is shared infrastructure and its incidental balances are not production invariants; client templates and fork simulations must verify that refunds and outputs return to Cart rather than strand value there. The router address is configured once with no runtime setter; new router versions or command families require a code change and review rather than an administrative allowlist update.

The policy is a stateless contract of its own, named by a cart implementation immutable rather than by proxy storage, so it keeps the same "audited upgrade, not administrative setter" property while staying outside the cart's EIP-170 budget. Calling it externally also gives the cart the `try`/`catch` boundary it needs to report which Order Line a rejected route belongs to.
