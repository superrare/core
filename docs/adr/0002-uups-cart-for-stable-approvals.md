# Keep the cart address stable through UUPS upgrades

Deploy the cart behind a UUPS proxy owned by the protocol multisig so seller transfer and mint approvals, EIP-712 signatures, Listing fill state, and Purchase Order replay state remain attached to one stable address across fixes and supported-fulfillment additions. This accepts the same upgrade-governance trust already present in SuperRare marketplaces; a non-upgradeable deployment was rejected because every replacement would require sellers to approve a new contract and would strand outstanding signatures and reusable Listings.

Upgrades must preserve the inherited OpenZeppelin linear storage, the Cart ERC-7201 namespaces, and the EIP-712 domain unless invalidation is intentional. Cart-owned state is split into `CartConfig`, `CartListings`, and `CartSettlement`; the initial field slots and offsets are captured in `src/cart/Cart.storage-layout.json`, with a proxy-upgrade canary test guarding them. Purchase execution is pausable, seller cancellation remains available while paused, `CartRoutePolicy` remains code-enforced rather than administratively extended, and upgrade verification covers storage, signatures, replay protection, Listing fills, and standing approvals.
